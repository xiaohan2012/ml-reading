# 第 2 层是干嘛的

第 1 层给了一把**尺子**($C(x)$ + $F$),但尺子只会给"一张已经摆出来的电路"打分,**不告诉你该把哪些 head 放进电路**。

- 数据挖掘类比:第 1 层 = **质量度量函数**,默认 pattern 已有;可你手上没有 $C$。
- **穷举不行**:(head × token 位置)的所有子集是组合爆炸。
- 所以需要一个**发现/搜索机制**,顺藤摸瓜把关键节点揪出来 → **path patching**(本文唯一原创核心技术)。

核心问题:**在一张稠密计算图里(几乎每条边都"存在"),哪些边对 IOI 真正起作用?怎么从输出端一层层往回追?**

# 第 1 块:为什么普通消融**不够**用来发现电路

朴素想法:逐个消融每个 head,看 $F$ 掉多少,掉得多的留下。→ 量的正是 Hydra 里的 **total effect**。三宗罪:

## 罪一:只有"节点"没有"边"——拼不出图结构

- 电路不是"一袋重要的 head",是**一张图**:谁喂给谁。
- 逐个消融顶多说"S-Inhibition 头重要、Name Mover 头重要",说不出关键那句:"S-Inhibition 头是通过写进 Name Mover 的 **query** 起作用的。"
- 没有边 → 只是一堆孤立的头,不是机制/算法。

## 罪二:total effect 混淆"直接"与"间接"——定位不了头在哪起作用

- total effect 分不清:这个头是**直接**往 logits 写答案(Name Mover),还是**通过改别的头**间接影响(S-Inhibition 改的是 Name Mover 往哪看)。
- 例:消融 S-Inhibition 头,logit diff 也掉——但它没在直接写 Mary。光看"掉多少",会把"终端写答案的头"和"上游调制的头"混为一谈。

## 罪三(最关键,正是本课题):self-repair 让 total effect **有误导性**

- 因 Hydra 效应,消融一个**真正重要**的 head,$F$ 可能**只掉一点点**(备份头补偿)。
- 按 total effect 排序卡阈值 → **系统性漏掉**真正的 Name Mover。
- **total effect 恰恰是被 self-repair 污染的那个量**,而 self-repair 是研究中心现象。

**path patching 为何绕过**:它测 **direct effect**,把其他头**冻结在干净值**、不许重算 → 备份头不激活 → 补偿被关掉 → $h$ 的直接贡献仍暴露。

> node 消融 = total effect(被自修复污染、只有节点级);path patching = direct/路径特定效应(抗自修复、边级分辨率)。

**堵漏洞**:"消融成对/成组的头测边?"→ (1) 还是 total-effect 家族,自修复照样污染;(2) 组合爆炸。path patching 用**单次干预**就拿到一条边的直接效应。

**小结**:普通消融三宗罪——只有节点没有边、混淆直接间接、被自修复误导。这三条正好定义了 path patching 必须具备的三个能力:**边级、直接、抗自修复**。

# 第 2 块:path patching 本体

## 一、三个要素

1. **源(sender)$h$**:想测的那个头。
2. **靶(receiver)$R$**:一组下游组件。第一步 $R$=logits;后面可能是"某些头的 query 向量"。
3. **路径集 $\mathcal{P}$**:从 $h$ 到 $R$ 的**直接路径**——只经**残差 + MLP**,**不经其他注意力头**。

两个输入:
- $x_{\text{orig}}\sim p_{\text{IOI}}$:**干净(clean)**,带完整任务信息。
- $x_{\text{new}}\sim p_{\text{ABC}}$:**污染(corrupted)**,名字换成随机 A/B/C,任务信息被抹掉。

## 二、具体怎么跑(三趟前向)

回忆第 1 层:**边 = 可分离项**——靶 $R$ 的输入(如 name mover 的 query)是一堆上游贡献的**和**,其中**一项**来自 $h$。path patching 就是**只把 $h$ 那一项从干净换成污染,别的项不动**:

1. **干净趟**:在 $x_{\text{orig}}$ 上跑,缓存所有激活(基准)。
2. **污染趟**:在 $x_{\text{new}}$ 上跑,单独缓存 $h$ 的激活(拿到 $h$ 的**污染值**)。
3. **打补丁趟**:回到 $x_{\text{orig}}$ 上跑,但**只在 $\mathcal{P}$ 路径上**把 $h$ 送给 $R$ 的那份贡献换成污染值;
   - 喂给 $R$ 的**其他所有贡献**保持干净;
   - $h$ 走**其他路径**(不通往 $R$ 的)也保持干净;
   - $R$ **之后**的层照常重算,让改动传到 logits。
4. 测 logit diff 相对干净趟**掉了多少**。

**一句话:除了"$h$ 对 $R$ 的那条信息"被污染,其余一切维持干净。→ 测出的变化只能归因于"$h\to R$ 这条边"。**

## 三、为什么"不经过其他注意力头"(要素 3 的灵魂)

- **只有注意力头能跨 token 位置搬信息**。
- 若允许 $h$ 先流经另一个头 $A$ 再到 $R$,测的是"$h$+$A$"合起来的效果,分不清。
- 限制在"残差 + MLP"(停在**同一 token 位置**)→ 把 **$h$ 自己直接送给 $R$ 的那份**隔离出来 → 边级、直接分辨率的来源。

## 四、为什么用"污染值"而非"零/均值"(干净/污染的角色)

- 换成污染值 = 反事实:"若 $h$ 在这条边上不再带 IOI 信息,输出会怎样?"
- logit diff 大幅下降 → $h$ 本来正是通过这条边把关键 IOI 信息送给 $R$。掉得越多,边越重要。
- 不用零:零分布外、误伤基线;污染值($p_{\text{ABC}}$ 真实激活)保留"这里有个名字"的语法背景,只抽掉"具体哪个名字"——精准只破坏任务信号。

## 五、测什么 + 为何抗自修复

- 测 **$h$ 对 $R$ 的 direct / 路径特定效应**。
- 抗自修复关键:第 3 趟里除 $R$ 之后的层,其他头**冻在干净值、不许重算** → 备份头不激活 → 补偿被关掉 → 即使 total effect 被自修复掩盖,直接贡献仍暴露。

## 六、和"普通 activation patching"对照

| | 普通 activation patching(整个 $h$) | path patching($h\to R$) |
|---|---|---|
| 换什么 | $h$ 的**整个**输出 | 只换 $h$ 送给 $R$ 的**那一份** |
| 影响怎么流 | 经**所有**下游路径(含其他头) | **只**经 $h\to R\to$ 输出 |
| 测到的量 | $h$ 的 **total effect**(节点级、混直接间接、被自修复污染) | **边级、直接、抗自修复** |

**落点**:path patching = "冻住全网、只污染一条边、看输出掉多少" 的因果探针。同时满足第 1 块的三个要求——**边级、直接、抗自修复**。
